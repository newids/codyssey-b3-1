# B3-1 수행 가이드 — 내가 만든 웹사이트를 인터넷에 올려 누구나 쓰게 하기

> 목적: 미션 요구사항(`docs/B3-1 ….md`)을 **빠짐없이, 증빙 가능하게** 수행하기 위한 단계별 절차서.
> 각 단계 끝의 **[증빙]** 항목은 평가에 제출할 스크린샷/출력물이다. 파일명 규칙은 `docs/screenshots/NN-설명.png`.

## 0. 전체 그림 (먼저 읽기)

```
사용자 ─HTTP:80─▶ Internet Gateway ─▶ Route Table(0.0.0.0/0→igw) ─▶ Public Subnet ─▶ Security Group(80 허용) ─▶ EC2(Nginx)
학습자 ─SSH:22 (내 IP만)──────────────────────────────────────────────────────────────────────────▶ EC2
```

| 구성 요소 | 값(권장) | 왜 이 값인가 |
|---|---|---|
| 리전 | `ap-northeast-2` (서울) | 미션 제약. **다른 리전에 만들면 무효** |
| VPC CIDR | `10.0.0.0/16` | 사설 대역, 넉넉한 크기. 미션 예시와 동일 |
| Public Subnet | `10.0.1.0/24`, AZ `ap-northeast-2a` | 퍼블릭 IP 자동할당 ON 필수 |
| 인스턴스 | `t2.micro` 또는 `t3.micro`, Ubuntu 24.04 LTS, EBS gp3 8 GiB | 프리 티어 |
| SG 인바운드 | 80 ← `0.0.0.0/0`, 22 ← `<내 IP>/32` | 미션 제약. 전체 포트 개방 금지 |
| IAM | 사용자 1개 + 최소권한 정책(`01-iam-policy-minimal.json`) | AdministratorAccess 금지, 루트 사용 금지 |
| 검증 방식 | **(B) `GET /health` → 200 "OK"** 를 기본으로 하고 (A) 브라우저 화면도 함께 캡처 | 둘 다 찍으면 어느 쪽을 선택해도 증빙이 남는다 |

**이름 규칙(태그)**: 모든 리소스에 `Name=b3-1-*`, `Project=codyssey-b3-1` 태그를 붙인다. 정리(cleanup) 단계에서 태그로 잔여 리소스를 찾는다.

## 1. 사전 준비 (약 1시간)

### 1-1. 루트 계정으로 해야 하는 단 한 번의 작업
루트 계정은 **IAM 사용자를 만드는 순간까지만** 사용한다. 이후 모든 작업은 IAM 사용자로 한다.

1. 루트 로그인 → **MFA 활성화** (보안 필수)
2. IAM → Users → **Create user** : `b3-1-operator`
   - "Provide user access to the AWS Management Console" 체크 → 콘솔 비밀번호 설정
   - 권한: **Attach policies directly** → **Create policy** → JSON 탭에 `docs/guide/01-iam-policy-minimal.json` 내용 붙여넣기 → 이름 `B3-1-MinimalEC2VPC`
   - ⚠️ `AdministratorAccess`, `PowerUserAccess`, `AmazonEC2FullAccess`(S3 등 무관한 권한 없음이므로 허용 범위이긴 하나 "필요한 작업 중심"이라는 요구에 비해 과함)를 붙이지 않는다.
3. (선택) Billing 대시보드를 IAM 사용자로 보고 싶다면 루트에서 **Account → IAM user and role access to Billing information → Activate** 후 정책에 `aws-portal:ViewBilling` 추가. 안 하면 정리 후 Billing 스크린샷은 루트로 1회만 확인.
4. 루트 로그아웃.

**[증빙]** `01-iam-user-policy.png` — IAM 사용자 상세 화면에서 연결된 정책이 `B3-1-MinimalEC2VPC` 하나뿐임을 보여줄 것.

### 1-2. IAM 사용자로 로그인 + CLI 설정 (CLI를 쓸 경우)
```bash
# IAM 사용자 → Security credentials → Create access key (CLI 용도) 후
aws configure                 # region: ap-northeast-2, output: json
aws sts get-caller-identity   # Arn 에 user/b3-1-operator 가 보여야 함 (root 아님)
```
**[증빙]** `02-caller-identity.png` — 위 출력. 루트가 아님을 증명.

### 1-3. 내 공인 IP 확인
```bash
curl -s https://checkip.amazonaws.com     # 예: 203.0.113.45  → SG 에는 203.0.113.45/32
```
가정/카페 와이파이는 IP가 바뀐다. **SSH 가 갑자기 안 되면 1순위로 다시 확인**한다.

### 1-4. 선택: 콘솔 vs CLI
- **콘솔**: 화면 캡처가 쉬워 증빙에 유리. 처음이면 콘솔 권장.
- **CLI**: `scripts/create-infra.sh` 한 번으로 전부 생성, `scripts/destroy-infra.sh` 로 역순 삭제. 재현·정리가 쉽다.
- 추천: **콘솔로 1회 수동 구축**(학습 목표 달성) → 삭제 → **CLI 스크립트로 재구축**해 비교. 시간이 없으면 하나만.

## 2. 네트워크 구성 (요구사항 4-1)

### 2-1. VPC
콘솔: VPC → Your VPCs → Create VPC → **VPC only**, Name `b3-1-vpc`, IPv4 CIDR `10.0.0.0/16`
```bash
VPC_ID=$(aws ec2 create-vpc --cidr-block 10.0.0.0/16 \
  --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=b3-1-vpc},{Key=Project,Value=codyssey-b3-1}]' \
  --query Vpc.VpcId --output text)
aws ec2 modify-vpc-attribute --vpc-id $VPC_ID --enable-dns-hostnames   # 퍼블릭 DNS 이름 부여
```
> "VPC and more" 마법사를 쓰면 NAT Gateway(시간당 과금!)가 끼어들 수 있다. 쓰더라도 **NAT gateways: None**, **Private subnets: 0** 으로.

### 2-2. Public Subnet
콘솔: Subnets → Create subnet → VPC `b3-1-vpc`, Name `b3-1-public-a`, AZ `ap-northeast-2a`, CIDR `10.0.1.0/24`
→ 생성 후 서브넷 선택 → **Actions → Edit subnet settings → Enable auto-assign public IPv4 address** ✅
```bash
SUBNET_ID=$(aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.1.0/24 --availability-zone ap-northeast-2a \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=b3-1-public-a},{Key=Project,Value=codyssey-b3-1}]' \
  --query Subnet.SubnetId --output text)
aws ec2 modify-subnet-attribute --subnet-id $SUBNET_ID --map-public-ip-on-launch
```
> 퍼블릭 IP 자동할당을 안 켜면 인스턴스에 퍼블릭 IP가 없어 **외부에서 절대 못 들어온다**. 트러블슈팅 단골.

### 2-3. Internet Gateway
콘솔: Internet gateways → Create → Name `b3-1-igw` → 생성 후 **Actions → Attach to VPC** → `b3-1-vpc`
```bash
IGW_ID=$(aws ec2 create-internet-gateway \
  --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=b3-1-igw},{Key=Project,Value=codyssey-b3-1}]' \
  --query InternetGateway.InternetGatewayId --output text)
aws ec2 attach-internet-gateway --internet-gateway-id $IGW_ID --vpc-id $VPC_ID
```

### 2-4. Route Table
콘솔: Route tables → Create → Name `b3-1-public-rt`, VPC `b3-1-vpc`
→ **Routes 탭 → Edit routes → Add route**: Destination `0.0.0.0/0`, Target `Internet Gateway` → `b3-1-igw`
→ **Subnet associations 탭 → Edit subnet associations** → `b3-1-public-a` 체크
```bash
RT_ID=$(aws ec2 create-route-table --vpc-id $VPC_ID \
  --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=b3-1-public-rt},{Key=Project,Value=codyssey-b3-1}]' \
  --query RouteTable.RouteTableId --output text)
aws ec2 create-route --route-table-id $RT_ID --destination-cidr-block 0.0.0.0/0 --gateway-id $IGW_ID
aws ec2 associate-route-table --route-table-id $RT_ID --subnet-id $SUBNET_ID
```
> VPC 생성 시 자동으로 생기는 **main route table** 에는 `local` 경로만 있다. 서브넷을 새 라우트 테이블에 **명시적으로 연결**하지 않으면 main 을 따라가 인터넷이 안 된다.

**[증빙]** `03-vpc-resource-map.png` — VPC 상세의 **Resource map** 탭 (VPC·서브넷·라우트 테이블·IGW 연결이 한 화면에 보임).
**[증빙]** `04-route-table.png` — `b3-1-public-rt` 의 Routes 탭에 `0.0.0.0/0 → igw-…` 가 보이는 화면 + Subnet associations.

## 3. 보안 그룹 (요구사항 4-3)

콘솔: EC2 → Security Groups → Create → Name `b3-1-web-sg`, VPC `b3-1-vpc`
Inbound rules:
| Type | Port | Source | 설명 |
|---|---|---|---|
| HTTP | 80 | `0.0.0.0/0` | 누구나 웹 접속 |
| SSH | 22 | **My IP** (자동으로 `<내 IP>/32`) | 운영자만 |

Outbound 는 기본(All traffic → 0.0.0.0/0) 유지. **All traffic / 0-65535 인바운드 규칙은 절대 추가하지 않는다.**
```bash
MY_IP=$(curl -s https://checkip.amazonaws.com)
SG_ID=$(aws ec2 create-security-group --group-name b3-1-web-sg --description "B3-1 web: 80 any, 22 my ip" --vpc-id $VPC_ID \
  --tag-specifications 'ResourceType=security-group,Tags=[{Key=Name,Value=b3-1-web-sg},{Key=Project,Value=codyssey-b3-1}]' \
  --query GroupId --output text)
aws ec2 authorize-security-group-ingress --group-id $SG_ID --protocol tcp --port 80 --cidr 0.0.0.0/0
aws ec2 authorize-security-group-ingress --group-id $SG_ID --protocol tcp --port 22 --cidr ${MY_IP}/32
```
**[증빙]** `05-security-group-inbound.png` — 인바운드 규칙 2개만 있고 22 가 `/32` 로 제한된 화면.

## 4. 키페어 + EC2 + 웹 서버 (요구사항 4-2)

### 4-1. 키페어 (재발급 불가 — 잃어버리면 인스턴스 다시 만들어야 함)
콘솔: EC2 → Key Pairs → Create → Name `b3-1-key`, ED25519, `.pem` → 다운로드 → `chmod 400 b3-1-key.pem`
```bash
aws ec2 create-key-pair --key-name b3-1-key --key-type ed25519 --key-format pem \
  --query KeyMaterial --output text > b3-1-key.pem && chmod 400 b3-1-key.pem
```
⚠️ `.pem` 은 `.gitignore` 에 포함되어 있다. **절대 커밋하지 않는다.**

### 4-2. EC2 시작
콘솔: EC2 → Launch instance
- Name `b3-1-web`
- AMI: **Ubuntu Server 24.04 LTS** (Free tier eligible 표시 확인)
- Instance type: `t2.micro` (없으면 `t3.micro`)
- Key pair: `b3-1-key`
- Network settings → **Edit**: VPC `b3-1-vpc`, Subnet `b3-1-public-a`, Auto-assign public IP **Enable**, Security group → **Select existing** → `b3-1-web-sg`
- Storage: 8 GiB gp3 (기본)
- Advanced details → **User data**: `scripts/user-data.sh` 내용 붙여넣기 (Nginx 설치 + `/health` 설정 자동화)
```bash
AMI_ID=$(aws ssm get-parameters --names /aws/service/canonical/ubuntu/server/24.04/stable/current/amd64/hvm/ebs-gp3/ami-id \
  --query 'Parameters[0].Value' --output text)
INSTANCE_ID=$(aws ec2 run-instances --image-id $AMI_ID --instance-type t2.micro --key-name b3-1-key \
  --subnet-id $SUBNET_ID --security-group-ids $SG_ID --associate-public-ip-address \
  --user-data file://scripts/user-data.sh \
  --block-device-mappings 'DeviceName=/dev/sda1,Ebs={VolumeSize=8,VolumeType=gp3,DeleteOnTermination=true}' \
  --metadata-options HttpTokens=required \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=b3-1-web},{Key=Project,Value=codyssey-b3-1}]' \
  --query 'Instances[0].InstanceId' --output text)
aws ec2 wait instance-status-ok --instance-ids $INSTANCE_ID
PUBLIC_IP=$(aws ec2 describe-instances --instance-ids $INSTANCE_ID --query 'Reservations[0].Instances[0].PublicIpAddress' --output text)
echo $PUBLIC_IP
```
**[증빙]** `06-ec2-running.png` — 인스턴스 상세: 상태 Running, 퍼블릭 IPv4, 서브넷, 보안 그룹이 보이는 화면.

### 4-3. SSH 접속 + 내부 검증
```bash
ssh -i b3-1-key.pem ubuntu@$PUBLIC_IP          # Amazon Linux 라면 ec2-user@
# 인스턴스 안에서:
systemctl status nginx --no-pager | head -5    # active (running)
curl -i http://localhost                        # HTTP/1.1 200 OK
curl -i http://localhost/health                 # 200 + OK
curl -I https://example.com                     # 200  → 아웃바운드 인터넷 OK (요구사항 4-1 마지막 항목)
```
user-data 로 설치했는데 nginx 가 없다면 `sudo cat /var/log/cloud-init-output.log` 로 설치 로그 확인. 수동 설치는:
```bash
sudo apt-get update && sudo apt-get install -y nginx
sudo tee /etc/nginx/conf.d/health.conf >/dev/null <<'NGX'
server { listen 80 default_server; root /var/www/html; index index.html;
  location = /health { default_type text/plain; return 200 "OK\n"; } }
NGX
sudo rm -f /etc/nginx/sites-enabled/default && sudo nginx -t && sudo systemctl reload nginx
```
**[증빙]** `07-ssh-internal-check.png` — 위 4개 명령 출력이 한 터미널에 보이는 화면 (프롬프트에 `ubuntu@ip-10-0-1-x` 가 보여야 EC2 내부임이 증명됨).

## 6. 트러블슈팅 보고서 (결과물 3)

**실제로 겪은 문제를 기록**한다. 구축 중 한 번도 막히지 않았다면, 아래처럼 **의도적으로 장애를 재현하고 복구**한 과정을 기록해도 된다(이것도 진짜 실험이다).

안전한 재현 실험 예:
1. SG 에서 80 규칙을 잠시 삭제 → 외부 `curl` 이 **timeout** 되는 것 확인 → 규칙 복구 → 재확인
2. 라우트 테이블의 서브넷 연결을 해제 → SSH/HTTP 모두 timeout + 인스턴스 안에서 `curl example.com` 실패 → 재연결
3. `sudo systemctl stop nginx` → 외부 `curl` 이 **connection refused** (timeout 과 다름!) → start
4. 휴대폰 테더링으로 IP 바꿔 SSH → timeout → SG 의 22 소스를 새 IP 로 갱신

각 건을 `docs/troubleshooting.md` 템플릿의 6단계(증상→가설→검증→조치→결과→재발방지)로 쓴다. 검증 단계에는 **실제 명령과 출력**을 붙인다. 대표 증상별 진단표는 같은 문서의 "참고 카탈로그"에 있다.

## 8. 리소스 정리 (요구사항 4-6, 결과물 4)

**순서가 중요하다**(의존성 역순). 콘솔에서 하면서 각 단계 화면을 캡처한다. CLI 는 `scripts/destroy-infra.sh`.

1. EC2 인스턴스 **Terminate** → 상태 `terminated` 확인 (Stop 이 아님! Stop 은 EBS 과금 계속)
2. EBS Volumes → 남은 볼륨 없음 확인 (DeleteOnTermination=true 면 자동 삭제)
3. Elastic IPs → 할당한 게 있으면 **Release** (연결 안 된 EIP 는 시간당 과금)
4. (만들었다면) NAT Gateway / Load Balancer / RDS 삭제
5. Internet Gateway → **Detach from VPC** → **Delete**
6. Security Group `b3-1-web-sg` 삭제 (VPC 삭제 시 함께 지워지긴 함)
7. Subnet 삭제 → Route table 삭제 → **VPC 삭제**
8. Key pair 삭제 (선택), 로컬 `.pem` 삭제
9. `scripts/check-leftovers.sh` 실행 → 전부 0 이어야 함
10. Billing → Bills / Free Tier 페이지에서 과금 항목 없음 확인

**[증빙]** `10-ec2-terminated.png`, `11-no-volumes-eips.png`, `12-vpc-deleted.png`, `13-check-leftovers.png`, `14-billing.png`(권장)

`docs/guide/02-평가-대비-체크리스트.md` 를 열어 전 항목에 ✅ 가 들어가는지 확인한다. 특히:
- [ ] 모든 리소스가 서울 리전에 있었는가 (스크린샷 우상단 리전 표시)
- [ ] SG 22 번이 `/32` 인가, 0.0.0.0/0 전체 포트 규칙이 없는가
- [ ] IAM 사용자에 AdministratorAccess 가 없는가, 루트로 작업한 흔적이 없는가
- [ ] README 에 (A)/(B) 선택과 IP 가 명시되어 있는가
- [ ] 트러블슈팅 6단계가 모두 채워졌는가
- [ ] 정리 체크리스트에 "삭제 완료" 근거(스크린샷/명령 출력)가 있는가
- [ ] `.pem`, 액세스 키가 저장소에 없는가 (`git grep -n AKIA` 로 확인)
